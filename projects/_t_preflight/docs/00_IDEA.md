## 한 줄

사내 문서(위키·PDF·회의록)를 한 곳에서 검색하는 내부용 검색 API와 최소 웹 UI.

## 문제

문서가 위키·드라이브·슬랙에 흩어져 있어 "그거 어디 있더라"에 시간이 든다. 각 도구의 검색은
자기 저장소 안만 본다.

## 사용자

50~200명 규모 회사의 직원. 관리자 1명이 소스 연결을 설정한다.

## MVP 범위 (가정)

- 소스 커넥터 2종(위키 export, 로컬 PDF 폴더)
- 색인 + 키워드 검색 API 1개(`GET /search?q=`)
- 결과 목록 웹 페이지 1개
- 로그인은 사내 SSO 하나

## 미해결

- 색인 갱신 주기와 방식(전체 재색인 vs 증분)
- 권한 — 문서별 접근 제어를 색인 단계에서 볼 것인가 조회 단계에서 볼 것인가
- 검색 품질을 무엇으로 판단할 것인가
