## API 계약

엔드포인트 3개. 모두 프록시 인증 뒤에 있다고 가정하고, 앱은 `X-Auth-User` 헤더 부재 시 401을 반환한다.

**`GET /search`**
- query: `q` (필수, 1~200자), `limit` (기본 20, 최대 50), `offset` (기본 0)
- 200: `{ "query": "...", "total": 42, "results": [ { "id": 1, "title": "...", "snippet": "...<mark>일치</mark>...", "url": "https://...", "source": "wiki", "updated_at": "2026-08-01T00:00:00Z" } ] }`
- 400: `{ "error": "q_required" | "q_too_long" }` / 401: `{ "error": "unauthenticated" }`
- 스니펫은 FTS5 `snippet()` 내장 함수 사용. 하이라이트 태그는 서버에서 이스케이프 후 삽입.

**`GET /healthz`**
- 200: `{ "ok": true, "documents": 12345, "last_indexed_at": "..." }` — 색인이 멈춘 것을 사람이 눈치채는 유일한 수단이라 MVP에 포함한다.

**`POST /admin/reindex`**
- 관리자 1명만 접근(`ADMIN_USERS` 환경변수의 SSO 계정 목록과 헤더 대조). 202 반환 후 백그라운드 실행, 동시 실행은 락 파일로 1개 제한.
- 403: `{ "error": "forbidden" }` / 409: `{ "error": "already_running" }`

기각: `GET /doc/:id` 본문 반환 엔드포인트. 원문 링크로 보내면 권한 검증을 원 저장소가 대신 해준다 — 우리 쪽 권한 버그의 폭발 반경이 스니펫 길이로 줄어든다.

- **권한 없는 문서의 검색 노출**: allowlist 결정이 누락된 채 "일단 전부 색인"으로 시작하면 인사·재무·평가 문서가 전 직원에게 노출된다. 되돌릴 수 없는 종류의 사고다(본 사람의 기억은 롤백 불가). 착수 전 관리자와 색인 대상 경로를 문서로 확정하고, 색인기는 **미지정 경로를 기본 거부**하도록 구현한다.

### High

- **SSO 전제 붕괴**: 리버스 프록시 인증이 없으면 `X-Auth-User` 신뢰 모델 전체가 무너지고, 헤더 위조로 인증이 우회된다. 프록시 없이 배포하면 안 된다 — 순서 5단계 착수 전에 인프라 담당에게 확인.
- **검색 품질 실패로 인한 무용지물화**: 트라이그램 키워드 검색이 실제 질의를 못 잡으면 사용자는 두 번 쓰고 떠난다. 순서 7단계(직원 5명 실사용)를 건너뛰지 말 것. `hit_count=0` 로그가 유일한 조기 경보다.

### Medium

- **스캔 PDF의 조용한 누락**: 텍스트가 없는 PDF가 색인 0바이트로 들어가 "검색해도 안 나오는 문서"가 된다. 사용자는 이걸 검색 품질 문제로 오인한다. 색인 로그 경고 + 관리자에게 목록 제공으로 완화.
- **XSS**: 문서 본문에서 뽑은 스니펫을 하이라이트와 함께 렌더한다. 이스케이프 후 태그 삽입 순서를 틀리면 사내 문서 내용이 스크립트로 실행된다.
- **색인 중단 무인지**: cron이 조용히 실패하면 몇 주 지난 색인을 계속 검색하게 된다. `/healthz`의 `last_indexed_at` 노출로 완화하되, 이걸 볼 사람이 없으면 무의미하다.

### Low

- **규모 초과로 인한 FTS5 한계**: 현재 가정 규모에서는 도달하기 어렵다. 도달 시 색인 파이프라인은 재사용하고 저장 계층만 교체.
- **`pdftotext` 외부 의존**: poppler 미설치 환경에서 색인기가 실패. 색인기 시작 시 바이너리 존재 확인 1줄로 조기 실패시킨다.
