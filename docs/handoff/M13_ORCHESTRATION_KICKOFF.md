## 2. 작업 순서 (사용자 지시 2026-08-27 — **중요도순 + 한계 개선**)

### 2.1 기능 잔여 (중요도순)

1. **`C-127`** — v1 문서 검증이 **경고만 하고 통과**시킨다(재생성 상한 후에도). 깨진 PRD가 다음 단계로
   간다. B-41 체크포인트가 그것을 "정상 산출물"로 결박한다는 점에서 지금 제일 아프다.
2. **`C-125`** — **아이디어 자체의 비평→개정 루프가 없다.** 레드팀 비평은 보고서로만 나오고 아이디어가
   고쳐지지 않는다(`critique_loop`의 수정 대상이 `tech_lead`뿐). versioned venture brief +
   PM↔RedTeam bounded loop가 후보이며 **원본 `00_IDEA.md`를 조용히 덮지 않는 것**이 제약.
3. **`B-44`/`B-43`** — `autopilot`·`autopilot-create`가 체크포인트를 우회한다(durable run에 project
   신원이 없다). B-41이 닫은 것은 v1 경로 4개뿐이라는 사실의 반대편.
4. **`C-123`** — v3 하류 task가 상류 `consumes` 문서 **내용을 못 본다**(도구 0 계약). 지금은 사람이
   briefing에 발췌를 넣어 우회. bounded 발췌 자동 동봉은 **새 승인 축 결정**이 필요하다.
5. **`C-136`**(summary·vault에 research mode 미렌더) · **`C-140`**(기본 `claude -p` 타임아웃 300초가
   리서치에 빠듯 — 실측) · **`C-139`**(영수증 한 장에 경로 기준이 둘).

고친다** — 재보지 않은 것을 고치면 그 수정이 무엇을 바꿨는지 말할 수 없다.

## 3. 작업 loop (실측으로 다듬어진 현행)

```
① 슬라이스 정의(오케스트레이터) — 경계·헌법을 프롬프트에 명시 · C-116 형식 mutation 보고 요구
② 계획이 필요하면 Fable 세션(read-only) → 설계 문서 → **Codex 계획 리뷰** → 반영 → 구현 발주
   (설계 문서는 승인되면 `docs/handoff/`로 **영구화**한다 — scratchpad는 세션과 함께 사라진다)
③ Agent(model:"opus", isolation:"worktree")로 구현 — **논리 단위 커밋을 남기게 하라**
④ 비평 2단: ⓐ 오케스트레이터가 핵심 주장 재검 + **mutation 최소 1종 독립 재현**(정확한 역치환으로만
   복원) ⓑ **Codex 적대적 리뷰** → finding을 **실물 검증한 뒤** 리비전 발행
⑤ cherry-pick → typecheck → focused → `npm run build` → **`npm test` 전체 1회**(배타 · 오케스트레이터만)
⑥ **CLI 스모크**(오케스트레이터 직접 · 파이프 없이 exit 측정) — 단위 테스트가 못 보는 것을 여기서 본다
⑦ docs: 판정 절(증명/미증명 같은 무게) + 대장 정본 + CONTEXT_SUMMARY + 킥오프
⑧ PR 스택(src / docs / dist 분리 · **한 PR은 코드 1000~1200줄**) → 순서 머지
   (`--delete-branch` 금지 · 뒤 PR은 base를 main으로 edit 후 머지)
```

## 4. 비싸게 배운 함정 (M12 열 + 이번 세션 일곱)

M12 킥오프 §4의 열(대장 처방 불신 · grep 정본 · 사용자/내 판단 분리 · 트리거 전 조이지 않기 ·
mutation red 아니면 결함 · 미증명은 오케스트레이터가 닫기 · **상태는 가장 늦은 판정 절이 정한다** ·
배송 상태도 주장이다 · **fixture가 그 mutation을 잡을 수 있는지가 선행 조건** · 사실이 바뀌면 앞 문장을
grep으로 전수 수색)은 그대로 유효. 추가:

11. **거짓 영수증은 새 상태를 도입할 때마다 재발한다.** 이번 세션에서만 **세 번**(B-40 killed →
    게이트 실패 → B-41 awaiting_approval). **새 상태를 만들면 소비자 전수**(CLI·summary·vault·영수증)를
    훑는 것이 체크리스트다.
12. **문자열 자격증명은 우회다.** "내부 전용" 인자를 공개 API에 두면 그것이 뒷문이다(B-41의
    `pipelineRunningStage` → WeakMap 불투명 신원으로 교체).
13. **"양쪽이 같은 함수를 쓴다"는 보고는 호출부를 grep해서 확인해야 한다.** 리비전 보고와 코드 주석이
    둘 다 그렇게 말해도 코드가 아닐 수 있다(C-126에서 `init`이 게이트를 우회 · B-40에서
    `extractDecision` 호출부 0건). **오케스트레이터 CLI 스모크가 이 부류를 두 번 잡았다.**
14. **닫힌 id를 정본 절 표에 남기지 마라** — 자기 검증 명령이 그것을 열린 것으로 센다(⑪·⑫·⑬에서
    세 번 반복). 등재 이력은 판정 절과 git이 갖는다.
15. **worktree에는 `node_modules`가 없다** → acceptance Test 22(M10)가 절대경로 `node_modules/.bin/tsx`를
    spawn해 FAIL 2가 난다. **환경 아티팩트**이며, 심링크로 **회피**하는 것과 **확인**하는 것을 구분해
    보고하게 하라.
16. **exit 코드를 파이프 뒤에서 재지 마라**(`| tail`의 코드가 잡힌다 — 이번 세션에도 한 번 오독).
17. **test provider가 계약을 만족하지 못하면 고칠 것은 계약이 아니라 provider다**(mock의 `## Decision` ·
    tokens.json `a11y` · `RESEARCH_REQUEST none` — 세 번 같은 판단).
