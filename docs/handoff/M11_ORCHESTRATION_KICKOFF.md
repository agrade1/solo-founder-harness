## 2. 작업 방식 — 이대로 하라는 것이 사용자 지시다

사용자가 2026-08-23에 명시했다: **"이 대화 세션은 명령 내리고 취합, 병렬 세션 따로 열어서 다른 fresh
세션에서 작업 진행해서 취합, 적대적 리뷰는 fable로."**

### 역할 분리

| 역할 | 누가 | 무엇을 |
|---|---|---|
| **오케스트레이터** | 이 대화 세션 | 결정 올리기 · 슬라이스 자르기 · 취합 · **`docs/**` 전부** · 통합 typecheck·suite · dist · PR·머지 |
| **구현 세션** | `Agent(isolation: "worktree")` · 병렬 N개 | 자기 소유 파일의 코드+테스트만 |
| **적대적 리뷰** | `Agent(model: "fable")` · read-only | 반증 시도. 구현자와 다른 세션 |

### 병렬을 성립시키는 조건 (이걸 어기면 직렬로 해라)

1. **파일 소유권을 겹치지 않게 자른다.** 프롬프트에 소유 목록을 **명시하고**, 그 밖을 고쳐야 하면
   **멈추고 보고**하라고 시킨다.
2. **`docs/**`는 오케스트레이터가 독점한다.** 로드맵·대장은 모든 슬라이스가 쓰고 싶어 하는 **공유 파일**이다.
   구현 세션에는 "대장에 적을 문장을 보고로 넘겨라"라고 시킨다 — 실제로 잘 써서 넘긴다.
3. **`npm test`·`scripts/acceptance.sh` 금지.** 배타 lock이고 서로 죽인다. focused만
   (`npx tsx --test <파일>`). 전체 suite는 **오케스트레이터가 취합 뒤 1회**.
4. **push·PR 금지.** commit까지만. 오케스트레이터가 cherry-pick해서 통합한다.
5. **live LLM 호출 금지**(구현 세션·리뷰 세션 둘 다). live는 오케스트레이터가 직접, 한 번에.

### 취합 절차 (이번에 실제로 밟은 것)

```
git checkout -b work/<slice> main
git cherry-pick <각 세션 commit>
npm run typecheck          # ← 세션들이 서로의 새 코드를 못 봤다. 여기서 처음 만난다
# 세션이 "미증명"으로 넘긴 것을 여기서 닫는다 (§4 함정 6)
npm test                   # 직렬 1회
<fresh Fable 적대적 리뷰> → 반영
docs 갱신(판정 절 + 대장) → 커밋 분리 → PR 스택 → 머지
```

## 3. 절대 타협하지 않는 것 (레포 규율)

`CLAUDE.md`·`AGENTS.md`가 정본이고, 그중 **이 방식에서 특히 자주 걸리는 것**:

- **과대주장 금지**가 최상위. 주석·커밋 메시지·테스트 이름이 증명보다 강하면 **A급**이다.
- **거짓 성공 영수증 금지.** 게이트가 막은 것과 "돌았지만 미확정"을 같은 값으로 적지 마라.
- **테스트 완화·삭제 금지.** 타입을 맞추려고 단정을 지우는 것도 위반이다.
- **acceptance를 만들면 mutation으로 red 확인.** 안 나오면 그 자체가 결함이다(§4 함정 5).
- **A급(과대주장·거짓 영수증·secret 유출) 즉시 수정 · B/C는 대장 기록 후 진행.**
- git: PR **1000줄 이하** 분할(**소스/dist 분리**) · `--delete-branch` **금지** · `git add -A` **금지**.
- 중요 결정은 **그 결정을 만든 코드의 주석**에 남긴다 — **기각한 대안과 그 이유를 함께**.

## 4. 이번 세션이 비싸게 배운 함정 여섯

**1. 대장의 처방을 그대로 믿지 마라 — 실측이 정본이다.**
`B-31`은 "`worktree prune`을 닫힌 action에 추가하라"고 적혀 있었다. 구현 세션이 재보니 prune은
`remove --force`가 못 하는 걸 못 하고, 경로 인자가 없어 argv로 좁힐 수 없고, 다른 worktree의
HEAD·refs를 지웠다. **처방을 기각하고 원인만 고쳤다.** 대장은 그때의 이해이지 판결이 아니다.

**2. 문서보다 grep이 정본이다.**
`grep -nE '\| open \|' docs/backlog/V3_AUTONOMOUS_ORCHESTRATION_ROADMAP.md`.
이 마일스톤에서 판정 절이 stale이었던 사례가 여러 번 나왔다(판정 ⑦은 완료 조건 재판정 표를 아예
빠뜨렸고, 그래서 "다 됐냐"의 정본이 한동안 옛 절이었다).

**3. 사용자 결정과 내 판단을 섞어 적지 마라.**
`C-86`에서 사용자는 "승인 축 추가"를 골랐는데 나는 그것을 **필수**로 만들고 판정 절에
"의도된 상태 — 이 결정의 내용이다"라고 적었다. 아니었다. 되돌리는 데 slice 하나를 썼다.
**"당신이 고른 것 / 내가 정한 것"을 보고에서 나눠 적어라.**

**4. 트리거보다 먼저 조이지 마라.**
같은 사고의 뿌리다. 대장 행에는 기한·트리거가 적혀 있다. 그보다 이르게 닫으면 **비용은 지금 내고
이익은 나중에도 안 온다**(위 경우 대가는 "이 harness를 쓰는 모든 사람의 추가 로그인"이었다).

**5. mutation이 red가 아니면 그것이 결함이다.**
이번에 두 번 겪었다: 자식 env에서 `CLAUDE_CONFIG_DIR`을 빼도 green(그 축을 아무도 단정하지 않았다) ·
spawn 직전 재확인을 빼도 green(죽은 코드였다). **둘 다 테스트를 추가해서 닫았다.**

**6. 구현 세션이 "미증명"으로 넘긴 것은 오케스트레이터가 닫는다.**
`B-31` 세션이 "타임아웃 값 자체를 관측하는 테스트가 없다 — 그 파일이 내 소유 밖"이라고 정직하게
넘겼다. 그걸 그대로 두면 그 slice의 핵심 변경이 무증명으로 남는다. **소유권 분리의 대가이고,
취합에서 갚아야 한다.**
